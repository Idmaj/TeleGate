# Security update 0.6.1

This local update is based on upstream commit
`316b403a26b929a6abe6b97d2675817cdd5a09bd`.

## Changes

- Revalidate read permissions before releasing MCP results, including direct
  history, chat details, media downloads, expanded searches and chat memory.
  Preserve unchanged one-time approvals without treating automatic rule
  reconciliation as owner approval. Reject policy changes during batch checks.
- Upgrade Electron from 40.10.6 to 45.2.3. Replace the archived GramJS package
  with pinned Teleproto 1.232.1 through the existing `telegram` package alias.
  Override vulnerable minimatch 9/10 dependencies in packaging with 11.0.5.
- Show bounded text/image attachment previews, exact byte sizes and SHA-256
  hashes. Require an individual content acknowledgement; unsupported previews
  also require an export for inspection. Do not automatically open exports.
  Exclude attachment approvals from batch approval.
- Display text forward sources and reject changes detected before sending.
  Disable media forwarding; reviewed file uploads remain available.
- Default to local review of synchronized access increases. Require explicit
  opt-in for direct routes in automatic proxy policies. Apply these safer
  settings once to existing profiles during upgrade.
- Add remote session revocation before removing credentials. On failure,
  retain the credentials and pause AI access for retry. Keep local-only removal
  as a separate confirmed action.
- Allow configured Windows signing and add `dist:signed`, which requires a
  signing certificate. Local unsigned builds remain available.

## Validation

- `npm test`: 93 tests passed, including synthetic HTTP regressions for
  revocation during reads, one-time approvals, file review enforcement and
  edited forward sources.
- `npm run test:approvals`: passed using an isolated Windows profile and mocked
  Telegram clients. Exercises real renderer/preload/IPC, attachment preview and
  export review, manual sync defaults, proxy opt-in and logout failure/success.
- `npm audit --json`: zero reported vulnerabilities, including development
  dependencies, at the time of validation.
- A synthetic StringSession generated by the previous GramJS version loaded
  and serialized identically with Teleproto. No real credentials were used.
- Windows portable packaging succeeded with the updated Electron runtime and
  minimatch overrides. No signing certificate was configured for this build.

## Remaining boundaries

No live Telegram account, production sign-in, real-account logout, or delivery
integration was tested. Verify these with a dedicated test account before
using a sensitive account. Electron still supports the synchronous secure
storage APIs used here, but warns that they will be removed in a future version.

These changes cannot prevent an authorized assistant provider from processing
returned data, protect session keys from malware running as the same Windows
user, recall previously delivered data, or undo writes already accepted by
Telegram. A file preview is not malware scanning. Exported inspection copies
remain on disk until deleted. Text forwarding still has a final comparison to
Telegram execution race because the Telegram API has no conditional forward
by content hash. Unsigned binaries do not establish publisher identity.

Local removal retains historical audit, memory and job data. MCP clients share
one bearer token and permission policy; connect only trusted clients. See
`SECURITY.md` for the complete trust boundary.
